# 编码规范

## 通用原则
- **第一性原理**：从根本问题出发，不照搬表面模式。
- **不过度工程化**：只做被要求的事，不为假设的未来需求设计抽象。三行相似代码好过过早抽象。
- **不擅自添加**：修 bug 不顺手清理周边代码；加功能不额外加配置项、文档、类型标注。
- **信任内部代码**：只在系统边界（用户输入、外部 API）校验，不为不可能发生的场景加防御性代码。

## TypeScript 约束
- **禁止 `any` 类型**（除非用户明确说明或最佳实践 skill 另有规定）。
- 优先用类型推断；需要显式类型时用具体类型或泛型。
- 避免 `as` 断言，除非确有必要并注释原因。

## NodeJS 约束
- **依赖必须用 npm 安装**，禁止通过 CDN 引入。
- 包管理命令用 `npm install`/`npm ci`，不用 yarn/pnpm（除非项目已用其他）。

## 代码风格
- 命名清晰：变量/函数名能自解释，避免 `temp`/`data`/`foo` 等无意义名。
- 不可变优先：优先 `const`，需要重新赋值才用 `let`，避免 `var`。
- 注释只写"为什么"，不写"是什么"（代码能表达的不写注释）。

## 调试
- 找不到 bug 时，可比对构建产物（dist/）与源码，确认编译/打包是否引入问题。
- 难以复现的 bug，用最小可复现示例隔离。
- 复杂问题多次未解决时，调用 Sequential Thinking MCP 获取灵感。

## 迁移与重构
- 从第一性原理出发，理解原有设计意图后再动手。
- 不浮于表面：不只为通过编译而改，要保证语义正确。
